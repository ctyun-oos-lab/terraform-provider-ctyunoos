# Resource: ctyun_oos_bucket_lifecycle_configuration

Provides an OOS bucket lifecycle configuration resource.

## Example Usage

```terraform
resource "ctyun_oos_bucket" "example-bucket" {
  bucket = "example-bucket"
}

resource "ctyun_oos_bucket_lifecycle_configuration" "example-lifecycle" {
  bucket = ctyun_oos_bucket.example-bucket.bucket

  rule {
    id     = "days-stable"
    prefix = "days/"
    status = "Enabled"

    expiration {
      days = 365
    }
  }

  rule {
    id     = "date-rule"
    prefix = "logs/"
    status = "Disabled"

    expiration {
      date = "2027-06-30T00:00:00.000Z"
    }
  }
}

output "bucket_lifecycle_configuration" {
  value = ctyun_oos_bucket_lifecycle_configuration.example-lifecycle
}
```

## Argument Reference

This resource supports the following arguments:

* `bucket` - (Required, ForceNew) The name of the bucket.
* `rule` - (Required) The rule configuration for bucket, supports id, prefix, status, expiration. When there are multiple rules, you can specify multiple rule blocks. See [`rule`](#rule) for details.

### `rule`

* `id` - (Optional) Specifies a unique identifier for the lifecycle rule. Value: 1~255 strings. When not specified, it is generated by the provider client: the prefix `tf-s3-lifecycle-` followed by a 26-character hexadecimal string, for a total of 42 characters.
* `prefix` - (Required) Specifies the object prefix of the lifecycle rule. Value: 0~1024 strings. Only objects that match the object prefix can be affected by this rule. In the same bucket, the lifecycle rules of the same type cannot have superimposed prefixes. If the value is null, the lifecycle rule matches the entire bucket.
* `status` - (Required) Specifies the status of the lifecycle rule. Value: `Enabled` (The lifecycle rule takes effect), `Disabled` (OOS ignores the lifecycle rule).
* `expiration` - (Optional) The expiration time rule, supports `days` and `date`.

The `expiration` configuration block supports the following argument:

* `days` - (Optional) Specifies how many days after the creation of the matched object the lifecycle rule takes effect. Value: positive integer. Either `days` or `date` is required, but they cannot be specified together.
* `date` - (Optional) Specifies the effective date of the lifecycle rule. OOS executes the lifecycle rule on objects created before this date. At this effective time, objects whose generation time is earlier than this time will be considered expired objects. Value: the date must be in ISO 8601 format at midnight UTC, in the format `YYYY-MM-DDT00:00:00.000Z`, for example `2026-10-11T00:00:00.000Z`. Either `days` or `date` is required, but they cannot be specified together.

## Attribute Reference

This resource exports the following attributes in addition to the arguments above:

* `id` - Name of the bucket.

## Import

In Terraform v1.12.0 and later, an `import` block can use the identity attributes to import a lifecycle configuration:

```terraform
import {
  to = ctyun_oos_bucket_lifecycle_configuration.example
  identity = {
    bucket = "example-oos-bucket"
  }
}
```

### Identity Schema

#### Required

* `bucket` - The name of the bucket.

In Terraform v1.5.0 and later, use an `import` block to import a lifecycle configuration by the bucket name:

```terraform
import {
  to = ctyun_oos_bucket_lifecycle_configuration.example
  id = "example-oos-bucket"
}
```

Using `terraform import`, import the lifecycle configuration:

```console
terraform import ctyun_oos_bucket_lifecycle_configuration.example example-oos-bucket
```
